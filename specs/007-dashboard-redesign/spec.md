# Feature Specification: 仪表盘页面重新设计

**Feature Branch**: `007-dashboard-redesign`

**Created**: 2026-07-10

**Status**: Draft

**Input**: User description: "帮我重新设计一下仪表盘页面，并且更新到007-dashboard-redesign"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后 10 秒内掌握系统态势 (Priority: P1)

管理员或审计员登录后，仪表盘首屏以清晰的视觉层级展示当前最需要关注的指标：资产规模与可用性、活跃远程会话、今日数据库操作量、安全告警（危险命令与失败登录）。关键数字使用统一卡片样式，支持一眼区分正常与需关注状态。

**Why this priority**: 仪表盘的首要价值是「进门即知全局」，统计卡片是最高频的信息入口。

**Independent Test**: 登录后无需滚动即可看到至少 4 类核心指标，且每项均有明确标签与数值（含 0 值场景）。

**Acceptance Scenarios**:

1. **Given** 系统中有 SSH、RDP、数据库三类资产，**When** 管理员打开仪表盘，**Then** 资产相关指标同时展示总数、在线数及类型拆分（主机 vs 数据库）
2. **Given** 当前存在活跃远程会话，**When** 用户查看仪表盘，**Then** 活跃会话数实时反映当前连接数，并区分今日累计会话量
3. **Given** 过去 24 小时内有危险命令被记录，**When** 管理员查看仪表盘，**Then** 安全相关指标以醒目方式提示，且可点击进入审计详情
4. **Given** 所有统计值为 0（新部署系统），**When** 用户打开仪表盘，**Then** 各卡片显示「0」及引导性说明，而非空白或报错

---

### User Story 2 - 按角色看到相关内容 (Priority: P1)

不同角色登录后，仪表盘展示与其职责匹配的内容：管理员看到完整运维与安全视图；运维人员侧重连接入口与自有授权资产概况；审计员侧重审计事件、命令风险与会话回放入口，隐藏无关的管理操作入口。

**Why this priority**: 堡垒机用户角色差异大，统一布局会造成信息噪音或权限困惑。

**Independent Test**: 分别以 admin、operator、auditor 账号登录，验证快捷入口与统计区块的差异符合角色权限。

**Acceptance Scenarios**:

1. **Given** 用户角色为 operator，**When** 打开仪表盘，**Then** 不展示用户管理类快捷入口，但可看到 SSH/RDP/SQL 连接入口
2. **Given** 用户角色为 auditor，**When** 打开仪表盘，**Then** 优先展示审计相关指标与「安全审计」「会话回放」入口，且无资产编辑类入口
3. **Given** 用户角色为 admin，**When** 打开仪表盘，**Then** 可见全部快捷入口及完整统计区块

---

### User Story 3 - 趋势与结构一眼可读 (Priority: P2)

仪表盘中部以可视化方式呈现：近 7 日会话创建趋势、资产类型/协议分布、命令安全比例（安全 vs 危险）。图表需带图例与数值标签，无数据时显示友好空状态。

**Why this priority**: 趋势与分布帮助发现使用高峰、资产结构偏差与安全风险积累。

**Independent Test**: 有历史数据时，用户能在 5 秒内读懂 7 日趋势走向和资产类型占比；无数据时看到明确提示。

**Acceptance Scenarios**:

1. **Given** 过去 7 天存在会话记录，**When** 查看趋势区域，**Then** 每日会话量以时间顺序展示，峰值日期可识别
2. **Given** 资产包含 SSH、RDP 及多种数据库类型，**When** 查看分布区域，**Then** 各类型占比清晰标注，总和为 100%
3. **Given** 无任何会话或命令记录，**When** 查看图表区域，**Then** 显示「暂无数据」及简要说明，布局不塌陷

---

### User Story 4 - 快捷抵达高频操作 (Priority: P2)

仪表盘提供常用功能快捷入口（远程连接、数据库查询、资产管理、授权、审计等），每项包含名称、简短说明与可点击区域，单次点击即可跳转至对应功能页。

**Why this priority**: 减少菜单层级，缩短从「了解情况」到「执行操作」的路径。

**Independent Test**: 从仪表盘点击任意可见快捷入口，均能在 1 次点击内到达目标功能页。

**Acceptance Scenarios**:

1. **Given** 用户有 SSH 连接权限，**When** 点击「SSH 连接」快捷入口，**Then** 进入 SSH 终端页面
2. **Given** 用户有数据库访问权限，**When** 点击「SQL 窗口」快捷入口，**Then** 进入数据库管理/查询入口页
3. **Given** 用户点击统计卡片（如「活跃会话」），**When** 卡片支持跳转，**Then** 进入对应的会话列表或详情页

---

### User Story 5 - 最近活动可追溯 (Priority: P2)

仪表盘展示最近远程会话与最近数据库查询记录（默认各 5 条），包含操作者、目标、协议/状态、时间等关键字段；列表项可点击进入详情或回放（若权限允许）。

**Why this priority**: 帮助管理员快速回答「谁在连什么」「最近跑了什么 SQL」。

**Independent Test**: 执行一次 SSH 连接和一条 SQL 查询后，刷新仪表盘能在最近活动区看到对应记录。

**Acceptance Scenarios**:

1. **Given** 系统中有最近会话记录，**When** 查看「最近会话」列表，**Then** 展示用户、资产名、协议、状态、开始时间
2. **Given** 系统中有最近 SQL 查询，**When** 查看「最近查询」列表，**Then** 展示用户、SQL 摘要、成功/失败状态、耗时、执行时间
3. **Given** 列表为空，**When** 查看对应区域，**Then** 显示空状态文案及引导按钮（如「开始连接」「打开 SQL 窗口」）

---

### User Story 6 - 数据保持新鲜且不打扰 (Priority: P3)

仪表盘每 30 秒自动刷新统计数据，并提供手动刷新；刷新时仅更新数据区域，不整页重载，不重置用户滚动位置；离开页面后停止后台轮询。

**Why this priority**: 兼顾实时性与性能，避免无效请求干扰用户。

**Independent Test**: 停留仪表盘 30 秒观察数据更新；切换至其他页面后确认无多余请求；手动刷新时页面其余区域仍可操作。

**Acceptance Scenarios**:

1. **Given** 用户停留在仪表盘，**When** 30 秒过去，**Then** 统计数据自动更新且页面不闪烁整页 reload
2. **Given** 用户点击「刷新」，**When** 请求进行中，**Then** 显示加载指示，其他区域仍可交互
3. **Given** 用户已导航至其他页面，**When** 原仪表盘组件卸载，**Then** 不再发起统计轮询请求
4. **Given** 统计请求失败，**When** 刷新出错，**Then** 保留上次成功数据，卡片显示降级状态（如「--」），不弹出阻断性错误

---

### Edge Cases

- 统计数据全部为 0：所有卡片与图表显示 0 或空状态，不出现布局错位
- 后端暂时不可用：保留缓存数据，显示降级指示，不白屏
- 超长 SQL 或资产名：列表中以摘要/省略展示，完整内容可通过悬停或点击进入详情查看
- 大屏与小屏：核心指标在常见桌面宽度下首屏可见；窄屏下卡片与图表自动重排，不出现横向溢出
- 高并发数据量：统计展示使用聚合结果，不受原始日志总量影响加载速度

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 仪表盘 MUST 在首屏展示核心指标卡片，至少包含：资产总数（含类型拆分）、在线/离线资产、活跃会话、今日数据库查询、危险命令数量
- **FR-002**: 指标卡片 MUST 在数值为 0 时仍显示「0」及可读标签，不得留空
- **FR-003**: 仪表盘 MUST 根据用户角色（admin / operator / auditor）过滤快捷入口与部分管理向指标，遵循最小权限原则
- **FR-004**: 仪表盘 MUST 展示近 7 日会话创建趋势，按日期聚合
- **FR-005**: 仪表盘 MUST 展示资产类型/协议分布（含 SSH、RDP 及已注册数据库类型）
- **FR-006**: 仪表盘 MUST 展示命令安全概况（安全命令 vs 危险命令比例或数量）
- **FR-007**: 仪表盘 MUST 提供角色可见的快捷入口，至少覆盖：SSH 连接、RDP 桌面、SQL 窗口；管理员额外可见资产管理、授权管理；审计相关角色可见安全审计入口
- **FR-008**: 支持跳转的指标卡片或快捷入口 MUST 在单次点击内到达目标功能页
- **FR-009**: 仪表盘 MUST 展示最近 5 条远程会话记录，字段含：用户、资产、协议、状态、开始时间
- **FR-010**: 仪表盘 MUST 展示最近 5 条数据库查询记录，字段含：用户、SQL 摘要、状态、耗时、执行时间
- **FR-011**: 列表与图表在无数据时 MUST 显示友好空状态（文案 + 可选引导操作）
- **FR-012**: 仪表盘 MUST 每 30 秒自动刷新统计数据，并提供手动刷新控制
- **FR-013**: 自动/手动刷新 MUST 仅更新数据区域，不触发整页 reload，不丢失滚动位置
- **FR-014**: 用户离开仪表盘页面后 MUST 停止统计轮询
- **FR-015**: 统计请求失败时 MUST 保留上次成功数据并显示降级状态，不阻断页面其余交互
- **FR-016**: 页面 MUST 提供明确的页面标题与一句话描述，说明当前为「系统运行状态与安全态势概览」

### Key Entities

- **仪表盘统计快照**: 聚合指标，含资产、会话、查询、命令安全、用户规模等当前值与今日累计值
- **7 日会话趋势**: 按自然日聚合的会话创建数量序列（最多 7 个数据点）
- **资产类型分布**: 按协议或数据库类型分组的数量与占比
- **命令安全统计**: 命令日志总量与危险命令数量
- **最近会话记录**: 最近 N 条远程连接会话，含用户、资产、协议、状态、时间
- **最近查询记录**: 最近 N 条数据库查询历史，含用户、SQL 摘要、状态、耗时、时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 的管理员用户能在登录后 10 秒内口头描述当前系统三项关键状态（资产、会话、安全）
- **SC-002**: 首屏核心指标在常规网络条件下 2 秒内完成首次展示（含加载态到数据态）
- **SC-003**: 自动刷新后数据延迟不超过 30 秒；手动刷新后 95% 的请求在 1 秒内返回并更新界面
- **SC-004**: 三种角色登录后，100% 的可见快捷入口均可一次点击到达正确功能页，且无越权入口暴露
- **SC-005**: 数据为空或请求失败时，100% 的统计区块显示明确空状态或降级状态，无白屏或裸报错
- **SC-006**: 在 1280px 及以上宽度的桌面浏览器中，核心指标卡片无需滚动即可全部可见

## Assumptions

- 仪表盘数据来源于系统现有资产、会话、查询历史、命令日志等记录的聚合统计
- 角色权限体系（admin / operator / auditor）已存在，仪表盘仅做展示层过滤
- 自动刷新采用定时轮询，不依赖实时推送通道
- 本次 redesign 聚焦仪表盘单页的信息架构、布局与交互，不包含新建独立报表模块或导出功能
- 视觉风格延续堡垒机现有暗色运维主题，保持与侧边栏及其他页面一致的体验
